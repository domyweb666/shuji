## 一、一句話

AI 站在**設定時刻**和**出事時**，不站在每天的核心動作上。它是照書辦事的顧問，不是自由發揮的聊天機器人。

## 二、已決定的事

| 決定 | 內容 | 理由 |
|---|---|---|
| 付費切法 | **搭建類免費，分析類付費**（多米 2026-11-08 選定） | 沒有好的開關句，核心動作就不完整，違反「免費版必須完整做得到核心動作」。付費的理由要等用幾週才會產生：想知道長得怎樣、下一步修什麼 |
| 付費形式 | 一次買斷，不訂閱 | 邊際成本接近零；訂閱會讓審核和使用者都問「每月付的錢換到什麼」 |
| 付費解鎖 | 週回顧建議、季稽核、小工具、收集物樣式 | 季稽核是最貴的一次呼叫（Sonnet），剛好在付費牆後 |
| 免費包含 | 核心動作全部、種下去助手、障礙版、對手偵測、三問診斷 | 這些是書裡證據最強、使用者最常出錯的地方 |
| 不做 | 每日提醒、每日建議、鼓勵長信、AI 代選習慣、行事曆時間盒 | 違反設計原則 1（開關在生活裡）與 2（每天不准有決定）；3-3 的研究顯示固定時間窗口反而不利 |
| 自我慈悲 | 不寫信。改成三問診斷＋固定結語「不是你的問題，是設計有洞」 | 把失敗歸到設計不歸到人格，這比鼓勵信更接近書的立場 |
| 行事曆 | 只把週回顧日、季稽核日排進行事曆 | 那是真的要坐下來想的時刻 |
| 裝置端模型 | **暫不採用** | Apple Foundation Models 目前不支援繁體中文（在年底計畫中）、上下文只有 4,096 token、推理弱。等繁中上線再評估搬搭建類任務 |
| 檢索方式 | **靜態檢索，不做向量 RAG** | 只有一本書，每個任務對應哪幾章是固定的。用程式碼路由到對應知識包，不會檢索錯，不用向量資料庫 |
| 版本順序 | v1 無 AI → v1.5 種下去助手＋三問診斷 → v2 其餘 | 先驗證核心動作有沒有人每天按 |

## 四、成本（2026-11 查價，上線前再對一次 Anthropic 官方頁）

價格依第三方整理：Haiku 5.5 每百萬 token 輸入 $0.10、輸出 $0.50、快取讀取 $0.01；Sonnet 5.5 $2／$10、快取讀取 $0.10。

| 任務 | 用量估計 | 單次成本 |
|---|---|---|
| 1、2、3、4 | 輸入 2–3k（大半是快取的知識包）、輸出 200–400 | ≈ US$0.0003–0.0005 |
| 5 | 輸入 4k、輸出 300 | ≈ $0.0006 |
| 6 | 輸入 8k、輸出 800 | ≈ $0.024 |

**一個使用者一年**：種 4 個習慣（約 12 次任務 1–4）＋ 52 次週回顧＋ 4 次季稽核 ≈ **US$0.17，約 5 塊台幣**。估錯十倍也只有 50 塊。一次買斷 NT$150 可以養這個人好幾年。

**真正的成本不在模型費：**

1. **後端**：金鑰不能放進 app，要有中繼伺服器。Cloudflare Workers 或 Supabase Edge Functions 免費額度撐幾千使用者。固定成本，不隨 AI 用量長。
2. **濫用**：公開端點會被當免費 LLM 用。上線前必做：Apple App Attest 驗證＋每台裝置次數上限（見提示詞文件的共同規則）。超過回 429，app 回到手動流程。
3. **Apple 抽成**：申請小型企業計畫，15%。

## 五、架構

```
iPhone app
  │  App Attest token ＋ 結構化輸入（JSON）
  ▼
中繼伺服器（Cloudflare Workers）
  │  驗證 token → 查次數上限 → 選任務 → 組系統提示（護欄包 ＋ 任務知識包 ＋ 任務指令，前兩段 cache）
  ▼
Claude API（Haiku / Sonnet）
  │  JSON
  ▼
中繼伺服器：驗 JSON 欄位、掃禁用詞 → 回 app
  │
  ▼
app 顯示；JSON 壞掉就重試一次，再壞就回手動流程
```

- 知識包是靜態檔案，部署時跟伺服器一起上；更新書的內容就重新部署，不需要資料庫。
- 使用者資料只在呼叫時送出該任務需要的欄位，不上傳整份紀錄、不存在伺服器。
- 手動流程永遠可用。AI 掛了、沒網路、次數用完，app 都能正常種習慣、記一節。

## 六、知識包的用法

| 檔案 | 給哪些任務 | 大小目標 |
|---|---|---|
| 知識包-護欄.md | 全部 | ≈1.5k token |
| 知識包-搭建.md | 1 | ≈2.5k |
| 知識包-障礙.md | 2、3 | ≈2.5k |
| 知識包-診斷.md | 4、5 | ≈2.5k |
| 知識包-稽核.md | 6 | ≈2k |

蒸餾原則：只留規則、驗收條件、好壞範例、用詞表、禁用清單；證據討論、案例、學派爭論都不進知識包。書的章節更新時，對照「來源」那一行重新蒸餾。
